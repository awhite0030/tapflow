# 기기를 네트워크에서 떼기

오프라인 배너, 실패하는 재시도, 캐시된 화면 — 리프트에 들어간 진짜 폰에서 앱이 하는 행동을 브라우저에서
확인하는 기능입니다. 툴바의 네트워크 버튼이 그걸 합니다.

**Android는 준비가 필요 없습니다.** 에뮬레이터를 비행기 모드로 넣기 때문에 tapflow가 이미 갖고 있는
것만으로 동작합니다.

**iOS는 맥에 한 번 설정이 필요합니다.** 이 페이지는 그 설정과, 하기 전까지 화면이 무엇을 말하는지를
다룹니다.

## 왜 iOS만 준비가 필요한가

iOS 시뮬레이터에는 끌 수 있는 무선 장치가 없습니다. 맥에서 도는 프로세스들이고 **맥의 네트워크 스택을
같이 씁니다.** 그래서 "오프라인"을 세 가지로 조립합니다.

| | 하는 일 |
|---|---|
| **1. 호스트 필터** | 그 시뮬레이터의 트래픽을 커널에서 떨군다 |
| **2. 주입 라이브러리** | 앱에게 경로가 끊겼다고 알리고, 이미 열린 연결을 끊는다 |
| **3. 상태 표시줄** | 신호 없음으로 바꾼다 |

**하나만으로는 전부 잘못된 결과를 냅니다.** 1층만 있으면 트래픽은 죽는데 앱은 온라인이라고 믿어서
오프라인 배너가 안 뜹니다. 2층만 있으면 앱은 오프라인 화면을 그리는데 **요청은 그대로 성공합니다** —
테스터가 재시도 로직을 확인했다고 서명하는데 아무것도 확인되지 않은 상태입니다.

준비가 필요한 건 **1층뿐**입니다. macOS 시스템 확장(content filter)이고, 맥 전체에 설치되지만
**효과는 당신이 토글한 시뮬레이터 하나에만** 미칩니다. 다른 시뮬레이터도, 맥 자신의 네트워크도
영향받지 않습니다.

## 준비가 안 됐을 때 화면이 하는 말

네트워크 버튼은 그대로 있고, 못 하는 것이 무엇인지 말합니다.

> **This Mac can't take devices offline.**
> Ask whoever runs tapflow on this Mac to set it up.

**이건 버그가 아니라 상태입니다.** 그리고 브라우저에서 볼 수 있는 사람은 고칠 수 없습니다 — 아래
설정은 **에이전트가 도는 맥 앞에 있는 사람**이 해야 합니다.

## 설치

::: warning tapflow는 아직 이 확장을 배포하지 않습니다
어떤 경로로 배포할지가 [#647](https://github.com/jo-duchan/tapflow/issues/647)에서 논의 중입니다.
커널에서 트래픽을 거르는 서명된 바이너리를 프로젝트가 배포한다는 건 tapflow가 하는 가장 큰 신뢰
요구라, 기본값으로 정하지 않고 결정으로 정하려는 것입니다. 그때까지는 직접 빌드해야 하고,
**유료 Apple Developer 계정이 필요합니다.**
:::

```sh
export DEVELOPMENT_TEAM=YOUR_TEAM_ID
packages/ios-agent/ios-netfilter/build.sh
```

| 필요한 것 | 이유 |
|---|---|
| 유료 Apple Developer 계정 | Developer ID 서명 + 공증 없이는 macOS가 시스템 확장을 안 올립니다 |
| 10자리 Team ID | `DEVELOPMENT_TEAM` |
| `notarytool` 자격증명 | 스크립트가 공증을 제출합니다. 설정 방법은 `build.sh` 헤더에 있습니다 |

빌드가 끝나면 결과물을 `/Applications`에 놓고 활성화합니다.

```sh
cp -R packages/ios-agent/ios-netfilter/build/stapled/TapflowNetFilter.app /Applications/
/Applications/TapflowNetFilter.app/Contents/MacOS/TapflowNetFilter --install
```

## 승인 — 사람이 직접 해야 합니다

활성화를 요청하면 macOS가 승인 알림을 띄웁니다. **이 승인에는 CLI 대체가 없습니다.**

**시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램 → 네트워크 확장**에서 tapflow 항목을 켭니다.

그래서 이 단계는 **에이전트가 도는 맥에서** 해야 합니다. 다른 자리에서 브라우저로 접속한 사람이
아무리 눌러도 승인 창은 그 맥에만 뜹니다 — 대시보드에 재시도 버튼이 없는 이유이기도 합니다.

승인하면 명령이 `0`으로 끝나고 네트워크 버튼이 바로 동작합니다.

## 안 될 때 — 종료 코드

`--install`과 룰 쓰기는 실패 종류마다 다른 코드로 끝납니다.

| 코드 | 뜻 |
|---|---|
| 0 | 성공 |
| 1 | 활성화 실패 |
| 2 | 설정을 읽지 못함 |
| 3 | 설정을 저장하지 못함 |
| 4 | 120초 안에 아무도 승인하지 않음 — 시스템 설정에서 승인하고 다시 실행 |
| 5 | 맥을 재시작해야 완료됨 |
| 6 | 45초 안에 시스템 확장 관리자가 아무 응답도 안 함 |

로그는 `/tmp/tapflow-netfilter-host.log`에 남습니다.

## 제거

확장은 `/Applications`의 앱과 별개로 등록되어 있으므로 앱만 지우면 안 됩니다.

```sh
systemextensionsctl list
```

목록에서 `dev.tapflow.netfilter.ext`를 확인한 뒤 시스템 설정의 같은 자리에서 끕니다. 교체하거나
제거한 버전은 **맥을 재시작할 때까지** `waiting to uninstall on reboot` 상태로 남습니다 — 정상입니다.

## 무엇을 신뢰하게 되는가

이 확장은 **커널에서 네트워크 flow를 보고 떨굽니다.** 맥 전체에 설치되고, root로 돕니다. tapflow가
사용자에게 요구하는 것 중 가장 큰 신뢰이므로 그 말 그대로 적습니다.

- **flow의 내용은 읽지 않습니다.** 어느 시뮬레이터의 것인지 판별하고, 그 시뮬레이터가 오프라인으로
  지정됐으면 떨굽니다. 그게 전부입니다
- **아무것도 밖으로 보내지 않습니다.** tapflow의 원칙 그대로, 앱 데이터는 당신의 네트워크를 떠나지
  않습니다
- **소스는 `packages/ios-agent/ios-netfilter/`에 있습니다.** 오늘은 직접 빌드하는 것이 유일한 경로라,
  당신이 서명한 것만 당신의 맥에서 돕니다
