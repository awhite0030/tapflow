# 네트워크 제어

툴바의 네트워크 버튼으로 기기 한 대를 오프라인으로 만듭니다. 오프라인 배너, 재시도 로직, 캐시된 화면처럼 네트워크가 끊겼을 때만 나오는 동작을 브라우저에서 그대로 확인할 수 있습니다.

## 사용법

기기 툴바의 네트워크 버튼을 누르면 그 기기가 오프라인이 됩니다. 다시 누르면 돌아옵니다.

버튼은 기기 단위로 동작합니다. 세션에 여러 대가 붙어 있어도 누른 기기 하나만 끊깁니다. 다른 기기와 에이전트 맥 자체의 네트워크는 영향을 받지 않습니다.

## 무엇이 끊기는가

- 새로 맺는 연결이 실패합니다.
- **이미 열려 있던 연결도 끊깁니다.** 앱을 다시 시작할 필요가 없습니다.
- 앱이 오프라인을 인지합니다. 경로 상태를 보는 앱은 끊겼다는 알림을 받으므로 오프라인 배너가 실제로 뜹니다.
- 상태 표시줄이 신호 없음으로 바뀝니다.

**로컬호스트는 살아 있습니다.** Metro 같은 개발 서버는 맥의 루프백으로 연결되기 때문에 기기를 오프라인으로 둬도 계속 붙어 있습니다. 디버그 빌드를 연결해 둔 채로 오프라인 동작을 볼 수 있습니다.

::: tip iOS 오류 코드는 실기기와 다릅니다
iOS 시뮬레이터에서는 `NSURLErrorNetworkConnectionLost`(`-1005`)가 납니다. 실기기를 기내 모드로 두었을 때 나오는 `NSURLErrorNotConnectedToInternet`(`-1009`)와 다른 값입니다. 오류 코드로 분기하는 앱이라면 두 값을 모두 처리하는지 확인하세요.
:::

## 요구 사항

- **Android**: 없습니다. 에뮬레이터를 기내 모드로 넣습니다.
- **iOS**: 에이전트 맥에 tapflow 네트워크 확장이 한 번 설치돼 있어야 합니다.

iOS 시뮬레이터에는 끌 수 있는 무선 장치가 없습니다. 맥에서 도는 프로세스이고 맥의 네트워크 스택을 함께 쓰기 때문에, 시뮬레이터 한 대의 트래픽만 골라 끊으려면 시스템 확장이 필요합니다.

설치는 에이전트가 도는 맥에서 관리자가 한 번만 하면 됩니다. 브라우저로 접속한 사람은 할 수 없습니다. 절차는 [문제 해결](/ko/guide/troubleshooting#network-not-set-up)에 있습니다.

::: warning 확장이 없으면 iOS 오프라인은 진짜가 아닙니다
확장이 설치되지 않은 맥에서도 버튼은 눌립니다. 앱은 오프라인 화면을 그리지만 요청은 실제로 성공합니다. 재시도나 오프라인 동작을 확인했다고 판단하기 전에 확장이 설치돼 있는지 확인하세요.
:::

## 문제 해결

**iOS 기기가 오프라인이 되지 않습니다**

- 에이전트 맥에 확장이 설치·승인돼 있는지 확인하세요. 절차는 [문제 해결](/ko/guide/troubleshooting#network-not-set-up)에 있습니다.

**오프라인인데 일부 요청이 성공합니다**

- 로컬호스트로 가는 요청은 의도적으로 통과시킵니다. 그 외의 요청이 성공한다면 확장이 설치되지 않은 상태입니다.
